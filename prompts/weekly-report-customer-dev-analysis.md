# 周报客户开发进度对比分析模板

## 适用场景

老板想了解**指定商务**本周 vs 上周的客户开发进度变化，评估达人开发效率、推进质量和增长趋势，为资源配置和管理决策提供依据。

**触发问题**：
- "张三的本周客户开发进度怎么样？"
- "李四上周和这周对比，推进有变化吗？"
- "看下王五的周报，达人开发有进展吗？"
- "这几个商务谁的客户开发效率最高？"
- "某人的周报内容给我分析一下"

---

## 分析角色

**主角色：CMO（达人生态与增长分析师）** — 负责客户开发进度、转化漏斗、增长质量分析

**辅助角色：CEO（全局经营操盘手）** — 负责资源配置决策、风险排序、管理动作建议

> 分析视角体现在分析深度里，不需要声明"CMO 视角"等标签。

## 数据获取流程

### 步骤1：确认周标识

```bash
# 获取本周权威周标识（Asia/Shanghai）
bin/cordys-boss weekly-report resolve-week
# 响应示例：weekKey=2026-W20, startDate=1746892800000, endDate=1747497599999

# 获取上周权威周标识（用本周 startDate 减 1 天，传给 resolve-week）
# 例如：startDate=1746892800000 → 减 86400000ms → 1746806400000
bin/cordys-boss weekly-report resolve-week 1746806400000
# → weekKey=2026-W19
```

> ⚠️ **禁止本地推导 weekKey**，必须通过 `resolve-week` 获取权威值。Asia/Shanghai 时区，周一为每周第一天。虽然 ISO 周编号 `W(n-1)` 的字符串推算是数学上安全的，但为保持一致性，统一通过 `resolve-week` 获取。

### 步骤2：获取本周周报

```bash
# 2.1 分页查询指定商务的本周周报
bin/cordys-boss weekly-report page '{"weekKey":"2026-W20","userIds":["userId001"],"status":"SUBMITTED"}'

# 2.2 获取周报详情（含四板块明细）
bin/cordys-boss weekly-report detail <reportId>
```

### 步骤3：获取上周周报

```bash
# 3.1 分页查询指定商务的上周周报
bin/cordys-boss weekly-report page '{"weekKey":"2026-W19","userIds":["userId001"],"status":"SUBMITTED"}'

# 3.2 获取周报详情
bin/cordys-boss weekly-report detail <reportId>
```

### 步骤4：补充客户数据（按需）

```bash
# 若需要了解某个具体达人的最新状态
bin/cordys-boss crm get account <accountId>
bin/cordys-boss crm customer-stat contract <accountId>
bin/cordys-boss crm customer-page opportunity <accountId>

# 若需要了解该商务的整体达人数据
bin/cordys-boss analysis customer-overview '{"ownerIds":["userId001"],"granularity":"WEEK"}'
```

### 批量对比（多商务）

```bash
# 获取本周团队所有已提交周报
bin/cordys-boss weekly-report page '{"weekKey":"2026-W20","status":"SUBMITTED"}'

# 获取上周团队所有已提交周报
bin/cordys-boss weekly-report page '{"weekKey":"2026-W19","status":"SUBMITTED"}'

# 或用看板快速获取汇总数据
bin/cordys-boss weekly-report dashboard '{"weekKey":"2026-W20"}'
bin/cordys-boss weekly-report dashboard '{"weekKey":"2026-W19"}'
```

## 数据对比维度

### 四板块数量对比

| 板块 | 本周 | 上周 | 变化 | 说明 |
|------|------|------|------|------|
| 待开发情况 (PENDING_DEV) | XX 条 | XX 条 | +N/-N | 新增线索/客户储备 |
| 已建联未寄样 (CONNECTED_NO_SAMPLE) | XX 条 | XX 条 | +N/-N | 当前处于建联阶段的客户 |
| 已寄样待跟进 (SAMPLE_SENT) | XX 条 | XX 条 | +N/-N | 样品投入中的客户 |
| 已排期待服务 (SCHEDULED_SERVICE) | XX 条 | XX 条 | +N/-N | 即将产出 GMV 的客户 |

**关键分析点**：
- 总盘子是否扩大？（四板块总量增长 = 开发积极性提升）
- 结构是否下沉？（已寄样+已排期占比提升 = 更多客户进入高价值阶段）
- 哪个环节出现断裂？（某板块数量骤降，或上游增下游减）

### 客户质量对比

| 维度 | 本周 | 上周 | 判断 |
|------|------|------|------|
| CLUE 占比 | XX% | XX% | 偏线索开发 vs 偏客户深耕 |
| CUSTOMER 占比 | XX% | XX% | |
| 跟进记录平均长度 | XX 字 | XX 字 | 跟进深度变化 |
| 有具体排期/日期的占比 | XX% | XX% | 推进质量 |

### 板块结构对比

> ⚠️ **注意**：周报四板块是**同一时点各客户的当前状态分布**，不是先后转化漏斗。一个客户只会出现在一个板块中（其当前所处阶段）。因此板块间不存在直接的"转化率"关系。
>
> 正确分析方式：比较各板块**绝对数量变化**、**占比变化**、以及**客户个体状态迁移**（通过匹配 target_id）。

| 指标 | 本周 | 上周 | 变化 | 判断 |
|------|------|------|------|------|
| 四板块总量 | XX 条 | XX 条 | +N/-N | 客户开发总盘子变化 |
| 待开发占比 | XX% | XX% | ±X% | 线索储备充足度 |
| 已建联占比 | XX% | XX% | ±X% | 建联深度 |
| 已寄样占比 | XX% | XX% | ±X% | 样品投入密度 |
| 已排期占比 | XX% | XX% | ±X% | 近期 GMV 预期 |
| 高价值板块占比（已寄样+已排期）| XX% | XX% | ±X% | 有效推进占比 |

**结构健康度判断**：
- 🟢 **理想型**：已寄样+已排期占比 > 50%，且较上周上升（推进有效）
- 🟡 **储备型**：待开发+已建联占比过高（> 70%），短期产出压力大
- 🔴 **断裂型**：已建联占比上升但已寄样+已排期占比下降（转化出问题）

## CMO 分析框架

### 1. 增长质量判断

**健康信号**：
- 四板块总量增长，且已寄样+已排期占比提升（总盘子扩大且结构下沉）
- CUSTOMER 占比稳定或提升（深耕而非广撒网）
- 已排期数量增长（短期 GMV 可期）
- 客户个体状态正向迁移数 > 负向迁移数（通过 target_id 匹配）

**风险信号**：
- 总量增长但已寄样+已排期占比下降（结构劣化，转化出问题）
- 待开发激增但已建联停滞（只收集线索不推进）
- 已建联很多但已寄样很少（建联质量差或选品不匹配）
- 已寄样很多但已排期很少（样品转化效率低，投入产出失衡）

### 2. 客户生命周期视角

将四板块映射到客户生命周期：

```
待开发 (CLUE)      → 获客阶段：是否有足够多的新线索流入？
已建联 (CUSTOMER)  → 激活阶段：建联后是否有有效互动？
已寄样 (CUSTOMER)  → 培育阶段：样品是否推动了合作意向？
已排期 (CUSTOMER)  → 成交阶段：是否转化为确定的 GMV 预期？
```

**判断标准**：
- 理想状态：四层均匀分布，每层都有稳定数量
- 亚健康：头重脚轻（待开发多，排期少）→ 转化效率问题
- 亚健康：头轻脚重（待开发少，排期多）→ 储备不足，后续乏力

### 3. 跟进质量评估

通过 `follow_record` 和 `remark` 字段评估：
- 跟进记录是否具体？（有日期、有动作、有结果）
- 备注是否有价值信息？（达人反馈、竞品情况、价格谈判）
- 是否存在敷衍？（记录为空或过于简单）

### 4. 交叉分析触发

| 发现的问题 | 交叉角色 | 联动分析 |
|-----------|---------|---------|
| 已寄样多但排期少 | CFO | 样品投入产出比是否恶化？ |
| 待开发多但建联少 | COO | 商务执行力是否不足？ |
| 排期多但历史履约差 | COO | 历史排期兑现率如何？ |
| 客户质量下滑 | CEO | 是否需要调整资源投入方向？ |

## CEO 决策支持

基于 CMO 的分析，CEO 需要给出：

### 1. 资源投入建议

| 商务状态 | 判断 | 建议 |
|---------|------|------|
| 结构健康且总盘子增长 | 🟢 明星 | 保持资源，可适度加码 |
| 总量增长但转化断裂 | 🟡 问题 | 诊断瓶颈（选品/话术/商务能力），针对性培训 |
| 总量停滞但转化健康 | 🟡 观察 | 增加线索供给，扩大上游 |
| 总量和转化双降 | 🔴 预警 | 紧急复盘，考虑资源重新分配 |

### 2. 管理动作

- **本周必须推动的事**：针对发现的具体问题，给出明确的管理动作
- **下周观察重点**：哪些指标需要持续关注
- **是否需要干预**：哪些情况需要老板亲自推动

## 数据缺失处理

| 场景 | 处理方式 |
|------|---------|
| 本周无周报 | 标注 `🚨 本周未提交周报`，分析上周数据，提示管理风险 |
| 上周无周报 | 仅分析本周数据，标注 `⚠️ 无上期对比数据` |
| 两期均无 | 标注 `🚨 该商务连续两周未提交周报`，触发执行力预警 |
| 周报为空（无明细） | 标注 `⚠️ 周报内容为空`，判断是敷衍还是确实无推进 |
| API 报错 | 标注 `⚠️ 数据获取失败`，不做基于此数据的判断 |

## 与四角色联动

本模板主要触发 **CMO** 分析，但会根据数据自动触发交叉分析：

- 成本相关（样品投入异常）→ **CFO** 介入
- 执行力相关（提交率低、跟进敷衍）→ **COO** 介入
- 资源决策（加人/减人/调整方向）→ **CEO** 介入
