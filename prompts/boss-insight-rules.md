# 老板洞察输出规则

## 目标

把 CRM 数据转换成老板可直接使用的经营判断。

## 默认输出结构

### 1. 结论
- 用一句话说清楚最重要的经营判断

### 2. 关键事实
- 列出 3-5 个关键数据点
- 必须是支撑结论的数据，不要堆字段
- 含环比/同比对比

### 3. 可视化图表
- 至少 1 张图表辅助理解
- 遵循 `visualization-rules.md` 规范

### 4. 风险提醒
- 指出异常、偏差、下滑、失衡或数据缺口
- 按严重程度排序，不并列

### 5. 建议动作
- 给出老板今天/本周可以推动的管理动作
- 具体到人、单、时间

## 角色化输出

根据问题类型自动选择角色视角：
- 成本/GMV/ROI → CFO 视角
- 效率/超期/目标 → COO 视角
- 达人/平台/增长 → CMO 视角
- 全局/风险/资源 → CEO 视角
- 复合问题 → 交叉分析

## 输出禁忌

- 不直接贴大段原始 JSON
- 不只做数据复述
- 不说"看情况""大概还行""保持沟通中"
- 不给执行岗视角的按钮式操作建议
- 不能没有图表（每次输出必须有可视化元素）
- 合同金额就是 GMV，不要说"回款""到账"
- 样品单价是售卖价预估，不要说"实际成本"

"这个月样品成本怎么样？"
