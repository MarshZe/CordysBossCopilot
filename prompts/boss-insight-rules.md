# 老板洞察输出规则

## 核心原则

把 CRM 数据转换成老板**可直接使用的经营判断**。
报告的唯一目的是帮老板做出更好的决策，不是展示数据分析能力。

## 倒金字塔结构

每次输出按信息价值从高到低排列：

```
第 1 层：结论 + 该干什么（5 秒）
第 2 层：关键证据 + 图表（30 秒）
第 3 层：详细分析 + 补充（需要时再看）
```

**先说结论，再给证据。** 不要让老板看了 3 段数据之后才知道你想说什么。

## 输出结构

### 1. 核心判断（一句话）

用一句话说清最重要的经营判断。这句话应该能直接指导决策。

**好的判断**：
> "本月 ROI 从 1:8 降到 1:5.5，成本集中在王五和赵六，但两人 GMV 转化率低于平均，需要本周复盘调整预算"

**差的判断**：
> "本月样品成本有所增长，ROI 有所下降，建议关注"

### 2. 关键数字（3-5 个）

只列支撑结论的数据，不堆字段。每个数字必须带对比。

```
- 本月样品成本 **3.2万**（环比 +18%）
- ROI **1:5.5**（上月 1:8，↓ 下滑明显）
- Top3 商务占总成本 **65%**
- 数据完整度 **85%**
```

### 3. 可视化图表（至少 1 张）

遵循 `visualization-rules.md` 规范。每次输出**必须有图表**。

### 4. 风险提醒

按严重程度排序，不并列。标注影响面和紧急度。

```
1. 🔴 ROI 跌破安全线 — 继续恶化将影响月度利润 XX 万
2. 🟡 成本集中度偏高 — Top3 商务中 2 人转化率低于均值
```

### 5. 建议动作

具体到**人、事、时间**。老板看完就能在周会上追问。

```
- 本周周会：优先复盘王五和赵六的达人转化效率
- 本周内：对 ROI < 1:4 的商务，建议下调样品预算上限
- 本月：抽查新品推广类工单的达人后续带货数据
```

## 角色视角自动路由

根据问题类型自动选择视角，**不需要声明角色名**：

| 问题类型 | 分析视角 | 风格 |
|---------|---------|------|
| 成本/GMV/ROI | 财务视角 | 数字精确，效率导向 |
| 效率/超期/目标 | 运营视角 | 执行导向，责任到人 |
| 达人/平台/增长 | 增长视角 | 生态思维，结构分析 |
| 全局/风险/资源 | 全局视角 | 决策导向，优先级排序 |
| 复合问题 | 交叉分析 | 多维度联动 |

## 输出禁忌

### 绝对不做
- ❌ 直接贴大段 JSON
- ❌ 只做数据复述（"达人总数 77"不是分析）
- ❌ 说"看情况""大概还行""保持沟通中"
- ❌ 给执行岗视角的操作建议
- ❌ 没有图表的纯文字输出
- ❌ 用 ASCII 框线艺术（`━━╔══` 在 webhook 中会错位）

### 口径纪律
- ✅ 合同金额 = GMV → 不说"回款""到账"
- ✅ 样品单价 = 售卖价预估 → 不说"实际成本""精确核算"
- ✅ 达人 = 客户 → 用"达人"不用"客户"（行业语言）
